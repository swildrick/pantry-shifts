## Interpretation

The codebase follows MUI closely: every UI file imports from the design system, and there are no hallucinated components or invented props. All nine findings are review-level, and eight of them are token discipline.

- Hardcoded colors are the main pattern. Four of the five raw hex values (#2F6B4F twice, #FCEFD9, #C9791B) already exist in src/theme.ts as green, amberLight and amber. That usually means the code was written without knowing the tokens existed. The fifth, #6b6b6b in SettingsPage, is close to the muted text token but not equal to it, so it also drifts visually.
- VolunteersPage.tsx is the worst file. The "Print roster" action is a plain HTML button with an inline style object (raw padding, color, radius) instead of an MUI Button, so it skips the theme's button styling entirely.
- Raw pixel spacing (20px, 4px, 10px 18px) appears where the theme's 8px spacing scale would do.
- The roster search TextField has only a placeholder, so screen readers get no reliable name.

Fixes, in order:
1. Replace the native button in VolunteersPage with <Button variant="contained">; that clears two findings and restores theme styling.
2. Swap the matching hex values for theme palette references (primary.main, secondary.main, secondary.light), and use text.secondary for the SettingsPage helper text.
3. Add an aria-label (or a label) to the search TextField, and move raw pixel values to sx spacing units (p: 2.5, mt: 0.5).

None of these rules look like noise for this repo, so no config changes are suggested.
